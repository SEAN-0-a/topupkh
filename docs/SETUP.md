# TopUpKH Setup GuideA Cambodian gaming marketplace (Eldorado-inspired) for Roblox creator assets,
creator services and game passes — with KHQR payment, buyer–seller chat,
support tickets and an admin commission ledger.

> This document is written for a beginner. Follow it top to bottom.

## 1. Prerequisites

| Tool | Version | Install |
|---|---|---|
| Node.js | 20.9+ | https://nodejs.org (LTS) |
| Git | any | https://git-scm.com |
| Supabase account | free tier ok | https://supabase.com |

Check installs:

```bash
node -v   # should print v20.x or newer
npm -v
```

## 2. Install & run (frontend)

```bash
npm install        # install dependencies
npm run dev        # start dev server -> http://localhost:3000
```

Other commands:

```bash
npm run build      # production build (Turbopack, Next.js 16 default)
npm run lint       # ESLint check
npx tsc --noEmit   # TypeScript check
```

## 3. Create the Supabase project & database

1. Create a project at https://supabase.com (pick the Singapore region —
   closest to Cambodia).
2. Save the database password somewhere safe.
3. SQL Editor → New query → run migrations **in this exact order** (one file
   per run):

   1. `supabase/migrations/0001a_legacy_rename_and_compat.sql`
      *(renames old prototype tables — `listings`, `orders`, `seller_wallets`,
      `payout_requests` — to `legacy_*`, keeping the data, and creates
      compatibility views so old pages keep working; no-op on fresh projects)*
   2. `supabase/migrations/0001_marketplace_schema.sql`
   3. `supabase/migrations/0002_order_lifecycle.sql`

   Quick fix only: if you hit
   `"Could not find the table public.games in the schema cache"` or
   `"tables games and eligibility_rules are missing"`, running
   `supabase/migrations/0003_games_table.sql` then
   `supabase/migrations/0004_games_categories_eligibility.sql` (0004 includes
   games too, so 0004 alone also works) fixes the homepage game/category
   sections — but you still need steps 1–3 above for the full marketplace.

What this creates:

- Profiles with **roles** (buyer / seller / support / admin). **The first
  account ever registered automatically becomes admin — that is you.** Register
  immediately, then every later signup is a buyer.
- Games, experiences, product categories and **eligibility rules**:
  - ALLOWED candidates: *Development Assets*, *Creator Services*, *Game Passes* (all `needs_review` — flip to `allowed` in the admin area after you verify rights).
  - PROHIBITED (DB-enforced, cannot be enabled without an explicit admin rule change): *Robux & Currency*, *Accounts*, generic *In-Game Items* — these violate Roblox Terms of Use.
- Products, orders, **payment attempts + events**, **transaction ledger**,
  payouts, conversations + messages (rate-limited and credential-spam-checked),
  support tickets, disputes, reports, reviews, notifications and an admin audit
  log — all with **Row Level Security** policies.
- A `platform_settings` row `commission_rate = 0.12` (12% — test value; change
  later in the admin dashboard, never in code).

## 4. Connect the app to Supabase

1. Supabase → Project Settings → **API** → copy the *Project URL* and the
   *anon / publishable* key (NOT the service-role key for the browser!).
2. Copy the env template and fill it in:

```bash
cp .env.example .env.local   # Windows: copy .env.example .env.local
```

3. Restart `npm run dev`.

## 5. Storage buckets (product images / purchase files)

In Supabase → Storage, create:

- `product-images` — **public** bucket (anyone may see listing photos).
- `purchase-files` — **private** bucket (download links must be generated by
  authorized code; stage-4 in-app download buttons use this).

Until upload UI is built, paste a public image URL into the product form.

## 6. Telegram (optional, for the manual payment pilot)

1. Talk to @BotFather → `/newbot` → copy the bot token.
2. Send your bot a message, then open
   `https://api.telegram.org/bot<token>/getUpdates` and copy the `chat.id`.
3. Put both into `.env.local` (`NEXT_PUBLIC_TELEGRAM_*`).

Admins then verify payment manually in the ABA/Bakong app and press **Confirm**
in the admin escrow queue. **This is a pilot process** — see
`docs/PAYMENTS.md` for the real integration plan and its limits.

## 7. First-run checklist

- [ ] Migration 0001 and 0002 executed without errors
- [ ] Registered your first account → role became `admin`
- [ ] Admin dashboard opens at `/admin` (will be wired in stage 7)
- [ ] Applied as a seller with a second account, approved it from admin SQL/admin UI
- [ ] Created a listing in an allowed category
- [ ] Bought it with the other account, verified payment, marked delivered, completed → ledger has rows

## 8. Deploying (when ready)

- Push to GitHub.
- Deploy on Vercel (Next.js 16 native) and add the environment variables from
  `.env.local` in the Vercel project settings.
- Supabase free tier pauses after 1 week of inactivity — monitor usage.

## Known limitations (honest list)

- Admin dashboard pages in `src/app/admin/*` still target the OLD prototype
  tables (`listings`, `seller_wallets`, …) and must be migrated to the new
  schema in stage 7 — check `docs/ROADMAP.md`.
- The old `/login`, `/sell` flows work with Supabase Auth but profiles are
  created by a DB trigger (make sure triggers exist after migrations run).
- Payment is the **manual pilot** only; no live provider, webhook, or payout
  automation exists yet. Do not launch publicly until `docs/PAYMENTS.md` and
  `docs/PAYOUTS.md` steps are done.
- Realtime chat UI lands in stage 5 (DB schema is already real-time-ready via
  Supabase Realtime on `messages`).
